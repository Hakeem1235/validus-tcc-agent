Selection (tools/policy.select): the latest SOP whose effective date is on or before received_at, plus the latest addendum for the folio's AMC in force on that date. Clause retrieval is filtered to those versions.

Key version differences encoded in rules.yaml: - 5.3/5.4: grandparent payments for a minor are allowed up to ₹50k with documents under v3.2, and rejected under v4.1. - 6.4: 10-day COB cooling exists only under v4.1. - 7.2: an invalid ARN means Direct under v4.1, and stays Regular with 30 days to fix under v3.2.

6. The one change

Top failure class: requests with no transaction of their own inherited an unrelated pending transaction on the same folio. - Affected 4 of the 5 failures: C24, C25, C30, C31. - C24 was the unsafe error: Aditi Menon's COB email picked up her pending ADD with an expired ARN, so it was classified as a purchase and proposed for PROCEED_MODIFIED.

Change (s3_resolve._match_txn): - A transaction is attached only with positive evidence: a UTR, amount or paying account that matches, or a compatible type. - Change-of-bank and out-of-scope requests attach one only on an exact UTR.

Follow-ups this exposed: - The first re-run (fix1) removed the unsafe error but showed that three purchases (C02 Hindi-English, C11, C21 cash) had only been classified correctly because of the stray match. - The rule-based intent classifier was therefore changed to return "unknown", not OTHER, when it has no signal. - Two parsing defects were also fixed: the single-line account regex (C14) and the KYC_PAYER document type (C26).

8. Cost per request

  • Median cost per request is $0.00 with 0 model calls. No LLM key was available in this environment, so every run used the rule-based extraction and template replies (extraction_method: "rules", reply_method: "template").
  • With LLM_API_KEY set, the trace records real usage_metadata token counts per call (extraction, vision per image, reply polish) and prices them from app/config.py. That cost has not been measured yet: run python eval/run_eval.py --label llm with a key to get it.

9. Not built, fragile, next

Not built: - S9 human review queue - email sending and the persistent case log (SOP 9.5) - policy-update assistant (S10) - public deployment: Docker and the GitHub CLI were not available here. Dockerfile and render.yaml are written and a clean-copy production start was smoke-tested locally; the public URL step is still to do.

Fragile: - Rule-based extraction of relationships, documents and intent on unusual wording when no LLM is configured. - Scanned images without vision are typed from the file name only. The error goes towards PEND, never towards accepting. - Single-transaction assumption per email. - Interpretations D1–D8 in docs/analysis.md.

Next: 1. Run the eval with Gemini enabled and record cost and latency. 2. Add 200+ real labelled desk cases as a held-out set. 3. Shadow mode against makers for a month. 4. Then consider auto-sending maker-only outcomes with no warnings (see FUTURE_WORKFLOW §4).
